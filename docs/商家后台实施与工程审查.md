# 商家后台实施与工程审查

## 实施结果

`/merchant` 提供与普通工作台分开的商家界面，共用登录、主题和请求组件。后台提供成员及邀请管理、项目授权、插件启停与定向试用、已配置连接的检查和启停、管理操作记录。管理请求以服务端身份控制库的角色及成员状态为准。

功能版本由部署方发布能力清单，商家可以选择兼容版本和开放范围。新任务记录受理时的功能版本和能力契约摘要。飞书、WebDAV、模型和店铺使用部署方提供的配置，凭据通过部署环境管理。模型和店铺的真实账号联调、PostgreSQL 备份恢复、Windows 安装包验收属于发布检查。

## 审查结论

代码已经达到本地及测试环境可联调的程度。商家后台前后端按领域拆分。管理状态和成功审计使用同一事务提交。成员关系留在身份控制库，企业业务设置和相关审计沿用工作区的数据归属，切库测试验证两部分可以一起查询。

审查期间修复了迟到的邀请重发请求覆盖新链接的风险。邀请重发带版本号，同一次重试可以读取当前结果，旧版本追加写入会被拒绝。停用插件的检查覆盖普通任务、定时任务和相关直接执行入口。后台与工作台还复用了同一请求模块、登录存储键和基础 UI 标签，减少两个入口随时间出现行为差异的机会。

## 工程化问题

| 优先级 | 发现 | 下一道工程验收 |
| --- | --- | --- |
| 高 | 仓库有依赖锁定、迁移、API 集成测试和 OpenAPI 导出。当前检出缺少自动 CI，也缺少实际可执行的 lint 与类型检查脚本。工程约定里的 Electron、React 和根目录命令与当前 Fastify、浏览器 JS、WinForms WebView2 实现不一致。 | 用实际技术栈更新工程约定，给合并设置依赖安装、语法检查、后端测试、OpenAPI 导出和浏览器冒烟门槛。 |
| 高 | 启用本机 FFmpeg 后，现有 MP4 标识回归测试报出容器时长 2.02 秒，断言要求恰好 2 秒。同一工具、同一测试在基线提交 `1b33cdb` 上复现。 | 固定 CI 的 FFmpeg 与 FFprobe 版本。结合视频帧及 AAC 封装精度核定允许误差，同时验证声音、标识和原文件完整性。 |
| 中 | 独立库切换和事务已在双 PGlite 数据库验证。生产 PostgreSQL 的真实锁竞争、备份恢复和迁移上线演练需要专用环境。 | 使用两个实际 PostgreSQL 库回归邀请并发、停用和任务受理竞态、迁移及备份恢复，再放开试点。 |
| 中 | 迁移器按文件名记录已应用迁移，并通过分号拆分 SQL。历史文件内容漂移以及包含分号的复杂 SQL 需要更严格的控制。 | 约定历史迁移文件不可变。引入校验摘要，扩展从上一发布版升级与迁移失败恢复的用例。 |
| 中 | 普通工作台的 `live-tasks.js` 仍超过 300 行，同时负责目录、提交、结果与定时视图。后台试用名单和项目授权选择器目前按页取得全部候选成员。 | 按业务拆分旧任务页。大企业的成员选择器使用服务端搜索与分页，保留已选项并限定 DOM 数量。 |
| 中 | 工作台与后台都经 Edge 浏览器走查。Windows 原生宿主和安装程序只有静态资源清单校验，安装、首次启动、本机持久化与卸载保留数据仍需真机验收。 | 在 Windows 10 和 Windows 11 用正式 WebView2 与打包依赖构建并走查安装流程。 |

## 本轮验收范围

- API 验证普通成员直访管理接口拒绝、跨企业隔离、邀请撤回及迟到的重试、成员停用恢复、项目撤权与归档、功能试用、历史任务版本、定时派发、连接权限和双库审计。
- Edge 验证登录、接受邀请、普通成员入口隔离、成员停用、项目授权、功能设置、管理记录、375 像素布局和主题弹窗。
- `npm test` 共 64 项，62 项通过，2 项需要指定 FFmpeg 工具路径。额外开启本机 FFmpeg 后，63 项通过，1 项复现基线 MP4 时长断言差异。
- OpenAPI 生成和 Windows 打包资源清单校验通过。Windows 原生安装和真实服务商账号的验收保留在部署阶段。
