# 商家管理后台开发计划

实施基线为仓库提交 `1b33cdb`。首版交付独立的商家后台，支持企业成员、项目授权、插件开关和管理操作记录。后续交付功能试用与版本记录，以及店铺、模型、飞书和网盘接入管理。按生产功能规划，开发与验收使用隔离测试环境和测试账号。

## 1. 入口与系统边界

- 商家后台入口为 `/merchant`。企业所有者和管理员在工作台内看到「商家后台」，从独立页面完成管理。普通成员继续使用工作台。浏览器和 Windows WebView2 使用同一后台页面。
- 管理后台复用现有登录凭据、企业成员关系和数据库路由。沿用现有 API 的身份校验，再对管理操作校验企业工作区、当前成员状态、角色及目标数据的归属。每次请求由后端读取当前权限，前端按钮按权限显示。
- 现有接口逐项迁移。成员、项目和插件的管理操作在后台集中呈现，普通工作台保留个人操作、项目访问和能力查询。所有仍可访问的旧管理接口同样应用实体归属和角色校验。
- 个人工作区与代理工作区使用原有业务入口。平台维护人员负责发布功能版本和维护接入目录，商家只管理本企业的启用范围、项目和连接。
- 前端单独注册商家入口和路由，复用现有主题、表格、表单、状态标签、确认弹窗和请求错误处理。后端沿用 Fastify 路由、参数校验、OpenAPI 和数据库分库逻辑，按成员、项目、插件和审计拆分模块。

## 2. 权限矩阵

| 操作 | 企业所有者 | 企业管理员 | 普通成员 |
| --- | --- | --- | --- |
| 进入商家后台与查看本企业管理记录 | 允许 | 允许 | 禁止 |
| 邀请、撤回和重发普通成员邀请 | 允许 | 允许 | 禁止 |
| 邀请管理员或变更管理员角色 | 允许 | 禁止 | 禁止 |
| 停用与恢复成员 | 可管理管理员和普通成员 | 仅普通成员 | 禁止 |
| 创建、归档与恢复项目，调整项目成员 | 允许 | 允许 | 禁止 |
| 启停本企业插件，后续设置试用名单 | 允许 | 允许 | 禁止 |
| 使用项目或插件 | 按项目访问规则和插件策略校验 | 按项目访问规则和插件策略校验 | 按项目访问规则和插件策略校验 |
| 查看接入状态 | 允许 | 允许 | 禁止 |
| 授权接入、轮换凭据、断开连接 | 允许 | 禁止 | 禁止 |

所有者账号受保护。成员停用只作用于选定的企业工作区，保留项目关系、历史任务、素材和账务记录。恢复成员后按其现有项目权限和功能策略重新生效。管理员操作涉及另一企业的资源时，接口统一返回资源不可见。未登录返回 401，当前工作区内角色不足返回 403，被停用的成员访问该工作区返回 403。

## 3. 第一版实施清单

| 模块 | 前端交付 | 后端与数据交付 | 验收结果 |
| --- | --- | --- | --- |
| 后台壳与工作区切换 | 登录入口、工作区选择、成员、项目、功能、操作记录导航。处理无权限、会话过期和加载失败 | 注册商家后台静态页面和资源。为管理入口增加统一的企业管理员校验。复用现有鉴权和工作区路由 | 多企业账号切换后页面与请求使用同一个工作区。旧请求返回时无法覆盖新工作区画面 |
| 成员与邀请 | 分页、按邮箱或姓名搜索、角色筛选、待接受邀请列表。提供邀请链接复制、撤回、重发、停用和恢复 | 复用成员列表、邀请创建和角色变更。增加成员状态、邀请业务 ID、撤回时间等字段及接口。数据库仅记录邀请令牌摘要 | 旧链接作废，重发只生成一条有效邀请。停用后旧会话立即失去该企业的新请求权限，其他企业可用 |
| 项目与授权 | 项目列表、创建、重命名、归档、恢复；详情展示已授权成员与授权操作 | 复用项目及成员授权接口。补齐分页、已授权成员查询、归档写入约束和权限变更记录 | 普通成员只能打开获准项目。撤销授权后，旧收藏或直达链接也无法继续读取。归档项目保留历史并能恢复 |
| 功能开关 | 按插件展示「可用」「企业已停用」「服务未配置」等状态。停用前提示影响，允许重新启用 | 复用插件目录和工作区开关。统一生效规则，新任务提交、定时派发和其他直接执行入口均检查功能策略 | 停用后普通用户无法提交新任务。已受理任务按原状态继续执行或结算，后台能查看历史结果 |
| 操作记录 | 按时间、操作类型、对象分页查询。查看操作者、结果与摘要 | 成员及邀请事件写身份库。项目与插件事件写工作区业务库。每条记录含工作区、操作者、动作、目标、安全摘要、时间和请求 ID | 变更和对应成功记录在同一数据库事务内提交。回滚后没有虚假的成功记录 |

成员、项目、功能页面统一处理空列表、校验错误、请求失败和并发更新。高影响操作显示企业名、目标对象和影响说明，提交期间按钮显示处理中。成功后读取服务端结果更新页面。失败保留输入并说明下一步，遇到旧版本写入冲突先刷新再确认。

### API 工作项

以下路径是实施规划。复用项以当前代码的路由和 OpenAPI 为准，新接口在实现时同步补齐请求、响应和错误结构。

| 能力 | 现有接口可复用 | 拟补齐 |
| --- | --- | --- |
| 企业身份 | 登录、会话恢复、工作区列表及请求鉴权 | `GET /v1/merchant/context` 返回当前企业及允许操作，供后台入口与导航使用 |
| 成员与邀请 | `GET /v1/members`、`PATCH /v1/members/:id`、`POST /v1/invitations`、接受邀请 | 成员查询和状态修改 `PATCH /v1/members/:id/state`。邀请列表 `GET /v1/invitations`，以及按业务 ID 撤回和重发 |
| 项目 | `GET/POST /v1/projects`、`GET/PATCH /v1/projects/:id`、项目成员授权与撤销 | `GET /v1/projects/:id/members`，补齐项目详情中的成员、状态和权限信息 |
| 功能 | `GET /v1/plugins`、`PUT /v1/plugins/:id/state` | 返回可用原因，写入携带待更新版本。第二阶段增加版本查询和发布范围配置 |
| 审计 | 身份事件和任务事件可参考现有实现 | `GET /v1/merchant/audit-events`，按工作区、时间、操作类型和对象查询，使用稳定游标分页 |

### 迁移与并发

1. 成员状态加在工作区成员关系上，已有成员回填为启用。保留历史外键。受邀者接受邀请时，事务内判断过期、撤回、是否已使用及邮箱。撤回、重发和接受使用同一邀请记录的事务锁。
2. 成员状态写入时同步记录身份变更事件。对企业独立库，沿用现有身份事件同步机制，并覆盖切库、备份与恢复。授权判断以身份控制库为准，企业数据按现有绑定数据库读取。
3. 项目归档、授予权限与撤销权限按本企业内的项目记录执行。对于引用项目的写入入口，统一检查归档状态和调用者可见性。已停用成员不能获授新权限。
4. 功能开关沿用工作区插件设置。管理更新与任务提交沿用现有锁和事务，明确记录哪个请求先提交。版本过期返回 409。邀请重发等会创建新对象的操作按请求 ID 去重，同一请求重试返回首次结果。成员停用后禁止新业务请求和新定时派发，停用前已受理的任务保留原归属并按原规则完成。
5. 管理事件只记录必要字段。联系邮箱按权限展示。邀请令牌、模型密钥、连接凭据和原始请求正文从日志与审计输出中剔除。

## 4. 第二阶段功能更新与试用

- 平台维护功能版本目录，记录插件、可选版本、更新说明、兼容性和发布时间。商家后台显示当前版本与可用更新，先支持「指定成员试用」「全企业启用」「停用」三个范围。
- 商家配置按企业保存，采用版本号处理同时修改。试用成员沿用现有项目权限。服务端统一计算功能是否可用，并让目录、页面入口、任务提交和定时派发读取同一规则。
- 任务受理时记录生效功能版本和对应执行配置的版本。撤回试用或切回上一兼容版本只影响后续任务。已接单任务按已记录版本处理，旧执行配置至少保留到关联任务完成。启用、试用范围变化、回退均进入操作记录。
- 验收覆盖试用者和非试用者同时访问、试用成员被停用、版本回退和两个管理员同时修改。历史任务须能查到执行版本。版本目录与执行器的兼容性通过发布环境验证后才允许选择。

## 5. 第三阶段第三方接入管理

首批复用现有连接能力。模型选择服务端已配置的别名，飞书和 WebDAV 使用已批准的连接定义。店铺接入依据实际授权方式分批开放。

1. 接入列表显示服务类型、绑定对象、连接状态、最近检查时间和可操作权限。状态统一为待配置、检查中、可用、异常、已断开。检查结果显示可操作的错误信息。
2. 所有者发起绑定与断开。连接检查通过后才启用。断开停止后续外部调用，保留既有资料、历史任务和回执。检查本身只执行读取或认证操作。
3. 凭据保存在服务端密钥存储，业务表记录引用和审计信息。界面只展示掩码或授权状态。检查请求采用明确的授权范围、允许的目标地址和超时；同一企业的绑定操作具备幂等控制。
4. 先交付模型别名、飞书与 WebDAV 的连接状态和绑定。店铺授权需要平台提供可联调的授权方式与测试店铺。商品写入继续走现有预览和人工确认流程，验收以实际平台回执为准。

## 6. 排期与分工

工期按一名前端与一名后端共同投入估算，为工作日。假设可使用同一套隔离联调环境，优先完成第一版。表中分工可以并行推进。

| 时间 | 前端 | 后端 | 交付门槛 |
| --- | --- | --- | --- |
| 第 1–2 天 | 确定页面导航、组件和空态 | 跑现有测试作基线，定权限矩阵、迁移及接口契约 | 管理账号和普通账号能分别进入对应界面 |
| 第 3–6 天 | 成员列表、邀请、状态变更与确认交互 | 成员状态、撤回和重发、身份事件及权限校验 | 邀请全流程、停用恢复、跨企业隔离通过 |
| 第 7–10 天 | 项目、成员授权、插件状态页面 | 项目归档与授权、插件策略、管理事件写入 | 普通工作台实测撤权、停用及历史任务访问 |
| 第 11–14 天 | 审计查询、异常提示，浏览器与 Windows 页面联调 | 集成测试、两类数据库迁移验证、试点发布排练 | 第一版全部验收项通过 |
| 第二阶段 5–7 天 | 更新详情、试用名单和回退界面 | 版本目录、生效策略、历史版本记录 | 指定成员试用和兼容版本回退通过 |
| 第三阶段 6–8 天 | 接入概览、检查状态、绑定和断开流程 | 接入适配、凭据服务和真实联调 | 已具备授权条件的服务按连接逐项验收 |

第一版计划约 **14 个工作日**。后续两阶段合计约 **11–15 个工作日**，店铺授权申请及等待时间单列。工期以现有测试基线和供应商联调条件复核。

## 7. 测试与发布验收

| 用例 | 通过条件 |
| --- | --- |
| 未登录、普通成员、企业管理员和所有者 | 管理页面、直达管理接口、修改角色各自返回正确结果。个人工作区拥有者不能进入商家管理范围 |
| 企业 A 请求企业 B 的成员、项目、开关或审计 | 不能读取、修改或取得目标是否存在的信息。篡改工作区标识和资源 ID 的组合时仍然隔离 |
| 现有会话下撤权、降级、停用与恢复 | 下一次请求按新权限判定。切换工作区、后退和刷新时不会显示旧企业缓存 |
| 邀请过期、撤回、重发和并行接受 | 至多有一笔有效加入。失效链接给出明确结果。成员和审计数据一致 |
| 项目归档与授权 | 已授权用户可查看归档历史，写入会被拒绝。恢复后按权限重新可写。撤权后直达链接失效 |
| 插件停用与任务并发 | 新提交按最终事务顺序决定，已经受理的任务保留历史和账务。定时派发检查同一规则 |
| 审计与独立数据库 | 每项成功变更可追溯，失败能返回可定位的请求 ID。共享库和独立库各自执行迁移、切换及恢复验证 |
| 前端联调 | 浏览器和 Windows WebView2 跑通后台入口、企业切换、状态变化和关键操作的二次确认。普通用户主流程回归通过 |

开发时先运行仓库实际提供的 `backend` 测试命令 `npm test`，并验证 `npm run openapi` 的输出。上线前用专用数据库做迁移和备份恢复演练，确认 `/health`、`/ready`、企业数据库状态和试点操作通过。先向指定商家开放后台入口，通过权限、数据和审计验收后再扩大范围。发生发布问题时，可按部署流程关闭新入口并回滚应用，数据库按演练过的版本和恢复步骤处理。
