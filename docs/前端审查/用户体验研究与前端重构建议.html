普通工作台与商家后台

从找到功能，到完成一次商品上新

一个卖家带着托特包的照片进来，应该能做出主图、核对细节，把选中的图放回这款包的草稿。隔天再来，应该能从上次离开的地方接着做。这是本次重构的主线。

核心决策

生产端围绕商品、素材和交付物组织；经营端围绕需要处理的记录组织；管理端围绕授权对象和影响范围组织。三者共用导航习惯、状态语言和基础控件，各自使用适合任务的信息密度。

方法与边界　基于本地现行代码、77 张既有预览图、重新运行的 Edge 浏览器任务走查、上一版布局样稿复测，以及下列公开一手资料。桌面走查使用 1366 × 768，手机使用 390 × 844 CSS 像素。账户、项目和商品均为隔离测试数据。没有访谈真实商家或采集生产流量。实测数值描述这套环境；用户心理与使用频率是待验证假设。

三条路径决定产品好不好用

第一次做主图的运营

用户的交付物　一张主体清楚、画幅合适、能够加入商品草稿的图片。他需要先认出手里的商品，再决定背景和规格。

走查　从首页「商品图片」点「查看」，在 15 个「详情」中选商品主图，看到当前环境未配置图片生成服务，再点「打开本地图片处理」。沿这条首页路径，三次页面跳转才进入可操作的本地表单。熟悉系统的人也可以从侧栏直接进图片处理。表单有 8 个可见输入或选择控件，处理前主内容区可见图片为 0。我选中已有包图，实际完成本地处理，再点「预览图片」才看到结果。本次验证的是本地处理路径，外部 AI 生成仍取决于部署配置。

改法　首页提供「制作商品主图」。第一屏直接选商品或上传图片；选中即出现原图和默认画幅。先选交付目标，系统据此给默认值。生成服务未配置时，现场给出「裁切并导出」及可执行范围，保留刚选的图。

第二天回来交付草稿的运营

用户的交付物　继续昨天那款包，而非重新识别工作区里的所有工具。他关心哪款商品、改到哪里、结果是否已保存。

走查　从首页经「商品档案 → 拼多多草稿 → 继续编辑」回到已保存的草稿。修改标题、切到素材库、用浏览器后退，标题恢复到上一次保存的值；离开期间没有弹出提示。首页「最近任务」显示能力标识，草稿列表另有自己的最近保存时间，两条线索需要用户自行关联。

改法　首页「继续工作」列最近编辑的对象，每项给缩略图、商品名、工作类型和保存时间。进入草稿后就地打开素材选择器；切页前识别未保存输入。分清「已保存在工作台」「待确认写入店铺」两种状态，保存草稿后继续回到同一商品。

给同事开通项目权限的商家管理员

用户的决定　“这位同事能不能看到这个项目？”他需要对准企业、成员、项目三个对象，并看见授权结果。

走查　从工作台进入商家后台，选择项目管理和具体项目，在隔离账号上实际撤销并重新授予成员访问，授权名单随结果更新。这条项目侧路径可用。若从成员页出发，那里显示的是企业角色与启停状态，项目授权需要转至项目详情。另一个管理任务「功能管理」在同页渲染 6 份表单、18 个可见下拉框和 6 个保存按钮。

改法　保留项目侧授权，同时从成员行提供「查看可访问项目」。修改前显示成员、项目和生效范围，修改后原行立即显示结果。功能管理默认给摘要表，点某行才编辑该项；列表筛选、滚动位置和行焦点都应保留。

优先级按潜在损失与是否阻断任务判断。此处的“高”表示应该先改；实际影响人数需要上线数据验证。

对上一版样稿的判断　大画布和单项设置抽屉值得保留。大幅商品封面只适合确有待续草稿的情形；空账户应优先呈现上传入口，多个草稿应显示可识别的列表。样稿中的「预览画幅」只验证了布局与裁切交互，尚未验证选图、生成、回填和保存能否连贯。窄屏隐藏侧栏后，还需要正式产品自己的页面选择入口。

最关键的数据约定　商品档案代表商品身份和 SKU；渠道草稿代表某个平台准备交付的内容；素材代表可复用文件；任务代表一次运行；结果记录产出和来源。一次创作携带企业、商品或草稿、所选素材、项目（可选）及返回位置。现有数据只有已核实的关联才显示为已关联；历史记录缺少商品关系时允许用户主动选择。

「从商品做图」要带入该商品或草稿的稳定 ID 和主图；「继续」直接恢复那份工作；「使用此结果」把选中的结果回填到明确的草稿。切换企业后重新鉴权并清除旧上下文。开发接入前核对各接口是否支持商品或项目关联，避免用同名、最近一张图或全局上一次选择来猜测。

每种页面只承担一种主要决定

首页让用户知道下一步做什么

新账户显示「上传商品图，开始做主图」，旁边提供从素材库选择。再次进入时优先呈现最多三条最近工作，带缩略图、商品名、成品类型、最近保存时间和「继续编辑」。出现失败或待确认任务时给出原因、影响和处理入口。余额放在账号区，提交前再展示本次消耗；不足时直接解释缺口。最近任务显示业务名称，例如「米白托特包 · 主图制作」。

创作页让用户始终看见自己在做哪件商品

桌面采用素材缩略图、中央画布、右侧设置。初始只展示所选商品、成品类型和输出比例；输入要求依任务出现。高级区容纳模型、精确尺寸、蒙版、多个 SKU、项目归属与定时。裁切或换色能即时反馈时，就在画布上显示；需要模型生成的变化明确标为待生成。加载中仍可离开并在任务中心恢复；重新生成保留旧结果。

提交按钮写清动作和已知费用，如「生成主图 · 3 积分」，费用读取服务端。服务未配置时说明能力边界并优先给出可用替代动作；无权限时指向可联系的管理员。完成区按用途提供「设为当前草稿主图」「下载」「继续编辑」，当下最相关的一项用主按钮。

商品、任务和管理页优先帮助比较与判断

商品列表固定缩略图、商品名与 SKU，另列草稿状态和最近修改。点击行进入详情，创建、导入、归档分别有明确位置。任务列表以商品或项目和动作命名，显示状态、开始时间和可恢复操作；失败详情区分授权、配置、输入和执行错误。只在选择了多行且后端支持时显示可执行的批量动作。

功能管理默认显示名称、企业开关、开放范围、服务可用性。点「设置」才展开单项面板。停用前显示目标企业、功能、对新任务的影响；高风险动作保留确认。成员页可按名称或邮箱搜索，项目授权和企业管理员角色分别命名。邀请操作完成后给出待接受状态、到期时间和复制入口。

中断与恢复是主流程的一部分

编辑页区分「有未保存修改」「保存中」「已保存」「保存失败」和「版本冲突」。先给站内跳转加离开保护、同页素材选择和明确的手动保存，再考虑经验证的自动保存。保存失败保留输入；并发编辑时展示差异，允许复制内容或重新载入。跨企业切换必须先处理当前编辑。模型重试沿用幂等机制，重复点击不重复扣费。

按可交付的业务路径实施

  1. 先修中断与窄屏导航

    前端在草稿编辑页记录修改状态，测试站内跳转、浏览器返回、保存失败、切企业。工作区导航在手机改成按钮打开的抽屉。交付门槛是修改能恢复或得到明确离开确认，两个端的所有入口可达。

  2. 贯通一款商品从素材到草稿主图

    设计、前后端共同定下商品、素材、任务、结果、渠道草稿的标识与权限。以已有本地处理先跑通真实闭环，再连接已配置的 AI 服务。覆盖无素材、服务未配置、余额不足、成功与失败。交付门槛是从结果回填到原草稿，刷新后仍能找到正确商品和图片。

  3. 用这条链验证新首页和创作编辑器

    先制作新用户与回访用户两种首页，提供可回退的试用入口。只显示来自真实数据的最近编辑和待处理工作。对照旧版跑下文任务，确认发现入口的速度、完成率和恢复能力达到目标。

  4. 推广到经营页与商家后台

    复用对象列表、单项编辑、未保存保护和状态反馈，优先迁移商品列表、任务、成员授权、功能开关。随后扩展到视频、SKU 批量、客服和其他页面。保留旧深链映射，所有敏感动作继续由服务端鉴权。

代码落点　首页与路由在 live.js，能力目录和提交在 live-tasks.js，本地处理在 live-image-studio.js，草稿表单在 live-drafts.js，商家设置和项目授权分别在 merchant-settings.js、merchant-projects.js。新增交互按领域拆分，先验证接口与真实状态，再推到其他页面。

让真实用户决定何时达标

建议先招 6 名日常制作商品内容的运营或设计人员、6 名做过成员或店铺管理的人。覆盖初次使用者和有同类工具经验的人。两版使用难度相当的不同商品，参与者轮换先测哪一版。主持人给业务目标，不说菜单名字；卡住后提供帮助要记为“有提示完成”。此为规划中的小样本测试。可用性测试方法

“给这款包做一张方形主图，放回它的上新草稿。”从登录首页到首次选对入口、确认商品、完成回填。分别记录等待生成时长与实际操作时长至少 5/6 人独立完成；首次选对入口的中位时间 ≤10 秒；放错商品 0 次
“昨天做到一半，现在改标题，去找一张图，回来继续。”查找原草稿耗时、重复录入、离开保护、刷新后文件归属至少 5/6 人在 20 秒内回到正确草稿；未告知的数据丢失 0 次
“让这位同事只访问秋冬项目，保留他的普通成员身份。”记录参加者是否混淆角色与项目，最后用成员账户实际验证可访问与不可访问项目至少 5/6 名管理员独立完成；错授企业管理员或其他项目权限 0 次
“只向一位同事开放试用，然后说明其他人能否使用。”记录是否找对功能、看懂影响范围；保存后分别用两种身份核对结果至少 5/6 人独立完成并正确解释范围；错误保存对象 0 次

单独检查视觉偏好。用同一商品、同一数据量，把两版各展示 5 秒，请用户指出当前对象、主要动作和一项待处理工作；再让他们说明最干扰视线的元素。记录原话和第一次点击。用行为检验层级，用偏好反馈调整色调、材质与字重。

上线观察。在获得合适授权后记录入口选择、素材选中、提交、返回草稿和保存成功等事件，只记匿名聚合、对象类别、结果和时长。按新老用户、桌面或手机、服务是否配置分组；同时看重复提交、未保存离开、失败后恢复和错误授权。先做一版小流量试用，再决定哪些页面值得全面迁移。

评审通过的标准

卖家能认出当前商品，看到下一步，知道会花多少、会改到哪里；离开再回来还能接着做。管理员能确认改的是谁、哪个项目，以及变更是否真的生效。
